# StoreFlow Demo 录屏脚本（5–7 分钟）

## 录制前

1. 启动 Compose，确认 `http://localhost:5174/health` 返回 200。
2. 准备 `output/pdf/storeflow_demo_operations_pack.pdf`；使用无 Key 模式可稳定演示，配置百炼/Tavily 时可额外展示远程证据与成本卡。
3. 固定输入：区域“上海浦东”、门店“浦东示范店”、SKU“BEV-500ML”；库存 144、日均销量 96、提前期 2 天、预算 1500、目标服务水平 0.92。
4. 关闭无关窗口；录制时不要显示 API Key、JWT 或本地环境变量。

## 分镜与台词

| 时间 | 操作 | 建议讲述 |
| --- | --- | --- |
| 0:00–0:35 | 打开首页与问题输入框 | “StoreFlow 服务区域采购负责人。它只做单门店、单 SKU、单周期的采购建议草案，不会自动创建采购单。” |
| 0:35–1:05 | 上传门店运营 PDF，创建固定问题 | “这里有库存日报、销量、促销和中央仓通知。问题是暴雨叠加饮料促销，库存只够 1.5 天时今天该订多少。” |
| 1:05–1:55 | 展示任务步骤、Agent 工具动作 | “模型不直接给订货答案，只能选择白名单只读工具。它先检查内部资料与历史经验，再发现配送维度缺证，才调用近期风险检索。” |
| 1:55–2:45 | 切到证据中心 | “三条独立证据通道并行获取：内部资料、公开风险、已批准记忆。结果用 RRF 融合、精排，再压缩成带 Evidence ID 的证据包；每个结论可回到来源。” |
| 2:45–3:30 | 展示风险事件、策略比较 | “LLM 不计算订货量。固定种子的 Monte Carlo 和 OR-Tools 比较正常订货、适度加订、高保障加订，统一看成本、缺货概率、服务水平、CVaR 和预算约束。” |
| 3:30–4:20 | 打开“模型与成本 / 检索与降级” | “这里能看到远程或确定性模式、token、耗时、Tavily 状态和降级原因。价格费率没配置时，系统明确写未配置，不虚构成本。” |
| 4:20–5:15 | 发起审核，选择批准并沉淀记忆 | “这是高影响边界。采购负责人可以批准、改约束、补证或拒绝；只有批准后的经验才能进入长期记忆。” |
| 5:15–6:00 | 新建同 scope 任务，展示记忆召回或记忆卡 | “下一任务会召回同区域/品类的已批准经验，但仍必须用当天的天气、促销和配送证据复核；冲突时标记为待复核，不用旧经验覆盖新事实。” |
| 6:00–6:25 | 回到架构或总结 | “这不是自由聊天机器人，而是受限 Agent 加确定性决策和持久化 HITL：动态补证由 Agent 完成，高风险计算与审批由可审计代码控制。” |

## 异常预案

- **百炼/Tavily 不可用**：说明这是受控降级，展示“模型与成本/检索与降级”卡与确定性结果；不要临场等待外部 API。
- **任务仍在运行**：切换到 Agent 运行轨迹，解释异步 Celery 任务、SSE/polling 和 checkpoint；继续展示已完成的证据、架构图或上一任务。
- **外部模式耗时长**：主动说明验收中外部闭环约 92–116 秒，当前是作品集单机原型；无 Key 路径用于稳定的现场演示。
- **被问到真实业务效果**：明确回答“目前使用模拟资料和公开信息，验证的是技术闭环与可追溯性，不声称已经接入企业 ERP 或产生线上节省。”
