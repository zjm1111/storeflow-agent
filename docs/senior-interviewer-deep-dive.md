# StoreFlow 深挖问答

## 为什么是 Agent，而不只是 RAG？

模型不是直接回答。它在白名单中选择下一步只读工具，读取 observation 后再选择；有步骤、外部检索与延迟预算，失败退回确定性策略。RAG 只是 Agent 的证据能力之一。

## 为什么并行检索？

内部资料、公开近期风险和已批准记忆互不依赖且只读，因此并行 Fan-out；RRF、重排序、压缩和决策依赖完整候选集，因此 Fan-in 后顺序执行。这样降低等待时间，不破坏审计顺序。

## 怎么防止幻觉与提示注入？

网页、PDF、记忆都被视为不可信数据；模型仅收到问题、受控范围、证据包和允许的 ID。RiskEvent 必须引用 Evidence ID，摘要不能脱离原文成为事实，外部 URL 经 SSRF 校验。

## 为什么仍保留人工审核？

订货带来缺货、损耗和现金占用的真实后果。系统只产生草案，通过 LangGraph interrupt 暂停，负责人可批准、改约束、补证或拒绝；没有写 ERP、下单、扣库存工具。

## 如何评测？

仓库有 48 个静态问题与 96 条可审阅金标证据作为离线回归。它验证结构、引用和降级行为；真实业务效果还需要冻结历史快照、历史回放和影子/A-B 设计。
