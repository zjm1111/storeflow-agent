# StoreFlow 产品定位

StoreFlow 是面向连锁零售企业区域采购负责人的供应链异常调查与补货决策 Agent。它在促销、天气、中央仓到货延迟与销量波动同时出现时，以结构化调查状态驱动证据检索、运营数据分析与定向补证，生成可审核的单周期订货建议。

## 解决的问题

采购负责人通常要在库存表、销量表、促销计划和配送通知之间先判断“为什么出现缺货风险”，再决定“今天订多少”。StoreFlow 维护需求、库存、配送与成本假设，输出正常订货、适度加订、高保障加订三种方案，并比较预期成本、缺货概率、服务水平和 CVaR。

## 首版边界

- 单区域、单门店、单 SKU、单补货周期；默认演示为瓶装饮料。
- 输入包含门店库存、日均销量、促销、中央仓提前期以及预算和服务水平约束。
- 系统仅形成采购建议草案，不能连接 ERP、创建采购单、扣减库存或修改业务数据。
- Agent 只能调用白名单只读工具；高影响策略须经采购负责人审核。

## Agent 行为边界

每一轮由百炼模型输出严格校验的 `{tool, reason}` JSON，控制器只接受内部资料检索、近期风险检索、已批准记忆检索、证据缺口检查、证据包、仿真和人审请求等白名单动作。代码负责执行权限、最多 6 步、最多 2 次外部检索、超时和 JSON 异常降级；模型不能下单、写库存、调用任意 URL 或执行命令。未配置模型时，系统会明确记录确定性回退，而不会伪装成自由自治。

RRF 检索漏斗同时展示内部资料、公开/Tavily 风险、向量/BM25 混合候选和已批准记忆。长期记忆仅作为受审核的业务先验，不能替代带 Evidence ID 的当前事实。

## 固定演示场景

周五至周日暴雨、饮料促销、中央仓配送可能延迟、门店库存仅够 1.5 天。Agent 先检查内部资料与已批准经验，再补充近期风险证据，形成带 Evidence ID 的风险事件和三种订货方案，最后等待人工审核。
